# iivnc-server

Windows 10 / 11 用の VNC サーバーです。この PC の画面を、VNC ビューア(相手側は
[iivnc-client](../iivnc-client) がおすすめ。TigerVNC などほかのビューアでも見られます)から
見たり操作したりできるようにします。

- **インストール不要。** `iivnc-server.exe` を好きな場所に置いて起動するだけ。ランタイムも DLL も要りません。
- **レジストリを使わない。** 設定は exe と同じ場所の `iivnc-server.ini`(UTF-8 のテキスト)だけ。
- **軽い。** exe 1 個(約 340KB)。接続が無いとき・画面が止まっているときの CPU 使用はゼロ
  (10 秒間の CPU 時間が計測の最小単位未満。2026-10-04 実測)。
- **速い。** 下の「速さのための工夫」と「測った結果」を参照。

## 使い方

1. `iivnc-server.exe` を起動します。最初は設定画面が開くので、**パスワード**(8 文字まで。VNC の決まり)を入れて OK。
   以後は通知領域(タスクトレイ)に常駐し、ポート 5900 で待ち受けます。
2. 初めて待ち受けるときに Windows Defender ファイアウォールの確認が出ます。使うネットワークにチェックを入れて許可してください。
3. 相手の PC で VNC ビューアを起動し、この PC のアドレス(設定画面の「状態」に出ます)を入れて接続します。

トレイのアイコンは、誰かが接続している間は緑になります。接続・切断は通知でも知らせます(設定で切れます)。
トレイのアイコンをクリックすると設定画面、右クリックで「全員を切断」「終了」。

Windows の起動時に始めたいときは、`iivnc-server.exe` のショートカットを
スタートアップ フォルダ(エクスプローラーのアドレス欄に `shell:startup`)に置いてください。
ただしこれはログインした後に始まります。**ログイン前から接続したいときは、次の「サービスにする」を使ってください。**

### ログイン前から使う(サービスにする)

設定画面の「Windows の起動時から」にある **「サービスにする」** を押すと、Windows のサービスとして登録します
(管理者の確認が出ます)。以後は Windows の起動時から動き、次のこともできるようになります。

- **ログイン画面**で、パスワードを打ってログインする
- **ロック画面**を解除する
- **UAC の確認画面**(管理者の確認)を操作する
- **Ctrl+Alt+Del** を送る(相手のビューアのメニューから)

ログインしている間は、今までと同じアイコンと通知がトレイに出ます。設定画面を開くときは管理者の確認が出ます。
アイコンの「通知領域から消す」はアイコンだけを消します(クリップボードの受け渡しのため、裏では動き続けます)。
やめるときは、設定画面の **「サービスをやめる」** を押してください。

登録するときに行うこと(やめると元に戻します):

- Windows のサービス `iivnc-server`(自動で開始、SYSTEM の権限)を登録する。Windows がレジストリにサービスの情報を記録します
- Ctrl+Alt+Del を送れるよう、Windows のポリシー `SoftwareSASGeneration` を設定する。元の値は ini に控えます
  (**iivnc-server 自身がレジストリに書くのは、ここだけです**)
- Windows ファイアウォールに、待ち受けるポートへの受信を許可する規則を足す(ログイン前は確認の画面を出せないため)

**気をつけること:** サービスは SYSTEM(この PC のすべての権限)で動きます。`iivnc-server.exe` を、一般のユーザーが
書き換えられる場所(ユーザーのフォルダなど)に置いたまま登録すると、その exe を差し替えた人やプログラムが
PC のすべての権限を得られてしまいます。登録のときにそうした場所なら警告を出します。
サービスとして動いている間は exe を上書きできないので、更新するときは先に「サービスをやめる」か、
サービスを止めてください。

### 設定

| 項目 | 内容 |
|---|---|
| パスワード | 操作できるパスワード。空のまま OK すると変えない |
| 見るだけのパスワード | こちらで入ってきた相手には操作させない(画面を見るだけ) |
| ポート | 既定 5900 |
| 受け付ける相手 | ほかの PC からも / この PC の中からだけ(127.0.0.1) |
| 送る画面 | すべての画面 / ディスプレイ n だけ |
| 見るだけにする | 誰にも操作させない |
| 接続・切断を通知で知らせる | 既定はオン |
| マウスが無い PC でもカーソルを見せる | 既定はオン。下を参照 |
| 接続されている間はスリープさせず、画面も消さない | 既定はオン。ビューアがつないでいる間だけ。切れたら元どおり |

パスワードが無いときは、「この PC の中からだけ」にしない限り待ち受けません(誰でも入れてしまうため)。

### ファイルのコピー＆貼り付け

iivnc-server と iivnc-client の間で、エクスプローラーのファイルをコピー＆貼り付けで受け渡せます(両方向)。

1. 片方の PC のエクスプローラーで、ファイルやフォルダを**コピー**する(Ctrl+C)。
2. もう片方の PC のエクスプローラーで、置きたいフォルダに**貼り付け**る(Ctrl+V)。

- コピーした時点で渡すのはファイルの一覧(名前・大きさ・日時)だけです。**中身は貼り付けたときに送ります。**
  貼り付けると、Windows のふつうのコピーの画面(進み具合・キャンセル)が出ます。
- 中身は VNC の接続の中で運ぶので、ファイアウォールに新しい許可は要りません。
- 「切り取り」でも、元のファイルは消さずにコピーになります。
- **見るだけ**の接続(見るだけのパスワード、サーバーの「見るだけにする」、ビューアの「見るだけ」)では使えません。
- 相手が iivnc でないとき(ほかの VNC)は使えません(何も送りません)。
- サーバーがサービスとして動いているときも使えます(ログインしている間)。そのときサーバー側でコピーしたものは、
  通知領域のアイコン(ログインしている人の権限で動く)が見つけて渡します。ファイルはログインしている人の権限で読みます。

### マウスが無い PC のカーソル

Windows 10 は、マウスがつながっていない PC ではカーソルを隠したままにします(画面にカーソルが描かれない)。
「マウスが無い PC でもカーソルを見せる」がオンなら、Windows が隠していても、Windows が持っている形
(矢印・I ビームなど。取れなければ標準の矢印)をビューアへ送るので、ビューア側ではカーソルが見えます。
サーバーの画面そのものには、これまでどおりカーソルは描かれません。
オフにすると、アプリが隠したカーソル(動画の全画面など)はビューアでも隠れます。

### ネットワークの許可

初めて待ち受けるとき、Windows が「このアプリにネットワークへのアクセスを許可しますか」とたずね、答えに合わせて
Windows ファイアウォールに規則を作ります。設定画面の **「ネットワークの許可」** に今ある規則が出ます。
**「許可を消す」** を押すと消せます(管理者の確認が出ます)。消すと、次に待ち受けを始めるときにまたたずねられます。

- 消すのは、**この場所の** `iivnc-server.exe` の規則だけです。別の場所に置いた iivnc-server の規則は消しません。
- サービスとして登録しているときは、サービス用の規則(ログイン前の接続に要る)は残します。

### ini のほかに PC に残るもの

iivnc-server 自身が書くのは ini と、`log=1` のときのログ(どちらも exe と同じ場所)だけです。
ほかに、Windows が次のものを記録します(2026-10-04、この PC のレジストリを検索して確かめた)。

| 何 | いつ | 消すには |
|---|---|---|
| Windows ファイアウォールの受信の規則(TCP・UDP) | 初めて待ち受けて、確認の画面に答えたとき | 設定画面の「許可を消す」 |
| 通知領域のアイコンと通知の記録(`HKCU\Control Panel\NotifyIconSettings` と `...\Notifications\Settings\NotifyIconGeneratedAumid_<番号>` など) | トレイにアイコンを出したとき | Windows が管理するもので、消すボタンはありません |
| サービスの登録、`SoftwareSASGeneration`、サービス用のファイアウォールの規則 | 「サービスにする」 | 「サービスをやめる」で元に戻します |
| 起動したアプリすべてに Windows が付ける記録(表示名の控え、起動回数など) | 起動したとき | ほかのアプリと同じく Windows が管理します |

## 速さのための工夫

- **変わった所だけを、GPU に教えてもらう。** Windows の Desktop Duplication(DXGI)で、変わった矩形と
  移動した矩形を GPU から受け取ります。画面全体を見回りません。変わった矩形だけを GPU から取り寄せます。
- **本当に変わったブロックだけ送る。** DXGI の「変わった矩形」はウィンドウ全体のように粗いので、
  32×32 のブロックごとに前の絵と比べて、本当に変わった所だけを送ります(カーソルの点滅なら 1 ブロック)。
- **ウィンドウの移動・スクロールは CopyRect。** DXGI が教える「移動した矩形」を、相手の手元にある絵の
  写しで済ませます(合成した絵での実測で、送る量が約 3 割減)。
- **全コアで符号化。** 送る範囲を 128×128 の単位に分け、色を数えて種類(塗りつぶし / 2 色 / パレット /
  JPEG / フルカラー)を決め、圧縮まで全コアで並列に行います。RFB の zlib ストリームは接続中ずっと続く 1 本ですが、
  各単位を「同じストリームの直前 32KB を辞書にして」独立に圧縮するので(pigz と同じ考え方)、相手から見れば
  普通の 1 本のストリームのまま並列にできます。出来た単位から順に送るので、符号化と送信も重なります。
- **自前の deflate と JPEG。** 依存ライブラリはありません。deflate のレベル 1 は、同じ条件(49KB ずつ、直前 32KB を
  辞書に)なら本家 zlib(zlib-ng)より速く(640 対 490MB/s)、よく縮みます(6.7% 対 9.9%。デスクトップ風の絵)。
  JPEG は SSE2(x64 の CPU なら必ずある)で 8 画素・8 列ずつ計算し、DCT と量子化は libjpeg と同じ計算なので、
  同じ品質なら大きさ・画質とも libjpeg と同等です。速さは libjpeg-turbo の約 1.2 倍の時間(v7 までの約 5 倍速い)。
- **引き寄せ式の取り込み。** 相手が絵を待っているときだけ取り込みます。送っている間に起きた変化は DXGI の側で
  まとまるので、回線が遅い相手でも無駄な取り込みをしません。待っている相手がいなければ何もしません。
- **カーソルは相手が描く。** カーソルの形と位置を送り、相手の手元で描いてもらいます(動かしても往復を待たない)。

## 測った結果(Core i7-12700KF(20 スレッド)・RTX 3070 Ti・4K 60Hz 1 枚。同じ PC の中の折り返し)

**ほかの VNC サーバーとの比べ合い(2026-10-06、v8)**

同じ受け手(`tools/compare.py`)と、同じ動く窓(`tools/srcwin.py`。1280×720、60fps で描き、左上にフレーム番号の縞)で、
実画面を取り込むサーバーを比べました。「見えた」は受け手が受け取れたフレームの数(60 が上限)、「遅れ」は
窓に描いてから受け手に届くまで、CPU はサーバーのプロセス(1 コア = 100%)。画質は「高画質」(JPEG 95・4:4:4。
ほかのサーバーは対応する範囲で)。UltraVNC は既定の CPU の上限(MaxCpu=40)と 1 秒あたりの上限を外した値です
(既定のままだと 21.5 更新/秒)。

| 絵 | サーバー | 見えた/秒 | 遅れ 中央 | 遅れ 95% | CPU |
|---|---|---|---|---|---|
| ふだんの操作(文字が流れ、四角が動く) | **iivnc v8** | 56.8 | 7.0ms | 7.9ms | 49% |
| 〃 | UltraVNC 1.8.3 | 40.4 | 14.9ms | 25.1ms | 33% |
| 〃 | TightVNC 2.8.90 | 57.1 | 16.0ms | 17.9ms | 82% |
| 動画(全面が毎フレーム変わる) | **iivnc v8** | 57.0 | 7.7ms | 8.9ms | 54% |
| 〃 | UltraVNC 1.8.3 | 41.1 | 16.7ms | 26.9ms | 44% |
| 〃 | TightVNC 2.8.90 | 13.7 | 68ms | 82ms | 107% |

iivnc の JPEG を作り直す前(v7)は、動画の絵で CPU 174%・遅れ 7.4ms でした。CPU の約 20%(1 コアの)は、
GPU から取り寄せた絵を読む前に GPU を待つ間、ドライバが CPU を回し続ける分です(下の「試してやめたこと」)。

**符号化だけの時間(1280×720 の絵 1 枚、1 スレッド)**

| 絵・画質 | v8 | v7 | libjpeg-turbo 3.1(参考) |
|---|---|---|---|
| 動画・JPEG 95 4:4:4 | 3.4ms | 17.3ms | 2.9ms |
| 動画・JPEG 80 4:2:0 | 1.8ms | 9.3ms | 1.5ms |
| ふだんの操作・JPEG 95 4:4:4 | 3.0ms | 11.1ms | 2.5ms |

**iivnc-client と組み合わせた通しの速さ(合成した 1920×1080 の絵、v8 と iivnc-client v10)**

| 絵 | 画質 | 更新/秒 | 帯域 |
|---|---|---|---|
| 全面が毎フレーム変わる(動画のような絵) | 高画質(JPEG 95・4:4:4) | 103(GDI)/ 118(GPU) | 710〜830 Mbps |
| 〃 | 劣化なし | 37 | 1400 Mbps |

実際の LAN では回線の速さで頭打ちになります(1Gbps なら、動画のような 1080p の絵で高画質 約 140 更新/秒相当の量)。
RealVNC とは比べていません(アカウントが要り、独自の暗号化が中心のため)。

**試してやめたこと**

- GPU から取り寄せた絵を読む前の待ちを、フェンス(`ID3D11Fence`)とイベントで眠って待つようにした。CPU は
  縞だけが変わる絵で 21% → 6% に減ったが、受け手に見えたフレームが 56.4 → 52.3/秒に減った(交互に 3 回ずつ)。
  なめらかさを優先して入れなかった。

## 対応しているもの

- RFB 3.3 / 3.7 / 3.8。認証は VNC 認証(パスワード)
- エンコーディング: Tight(JPEG あり)、ZRLE、Raw、CopyRect
- 疑似エンコーディング: カーソル、カーソル位置、画面の大きさ(DesktopSize / ExtendedDesktopSize)、
  画質・圧縮の強さ(TurboVNC の細かい画質・間引きも)、QEMU のキー(スキャン コード)、拡張クリップボード(UTF-8)
- iivnc どうしだけ: ファイルのコピー＆貼り付け(独自の疑似エンコーディングとメッセージ 105)
- 画素形式: 8 / 16 / 32 ビット(色の表を使う形式も)
- 複数の相手の同時接続(共有しない接続が来たら、ほかを切る)
- 動作を確かめたビューア: iivnc-client、TigerVNC 1.16.2(Windows 版)。UltraVNC 1.8.3・TightVNC 2.8.90 のビューアは、つながって更新を受け続けることまで確かめた(絵が正しいかは見ていない)

## できないこと・気をつけること

- **通信は暗号化しません。** パスワードはそのまま流れません(VNC 認証)が、画面やキー入力は暗号化されません。
  インターネット越しに使うときは VPN か SSH のトンネルを通してください。
- パスワードは 8 文字まで(VNC 認証の決まり)。同じアドレスから 60 秒に 5 回間違えると、そのアドレスを 60 秒締め出します。
- トレイ常駐で動かしているときは、**UAC の確認画面・ロック画面・サインイン画面は映らず、操作もできません**。
  Ctrl+Alt+Del も送れません。これらが要るときは「サービスにする」を使ってください。
- トレイ常駐を普通の権限で動かしていると、**管理者として動いているウィンドウ(タスク マネージャーなど)は操作できません**(UIPI)。
  サービスにすれば操作できます(SYSTEM で動くため)。
- カーソルの形を受け取れないビューアでは、カーソルが見えません(画面の絵にカーソルを描き込まないため)。
- 複数のディスプレイ・回転した画面・HDR の画面での動きは、この PC(4K 1 枚)では確かめていません。
  回転した画面があるときは DXGI を使わず GDI で取り込みます。

## コマンド ライン

```
iivnc-server.exe                 起動してトレイに常駐し、待ち受ける
iivnc-server.exe -settings       設定画面を開く(動いていればそちらで)
iivnc-server.exe -exit           動いている iivnc-server を終わらせる(終わるまで待つ)
iivnc-server.exe -ini <path>     別の設定ファイルで動かす
iivnc-server.exe -log            iivnc-server.log に動作の記録を書く
iivnc-server.exe -install-service    管理者で: サービスとして登録して始める
iivnc-server.exe -uninstall-service  管理者で: サービスをやめる(ポリシーとファイアウォールも戻す)
iivnc-server.exe -remove-firewall    管理者で: ファイアウォールの、この exe の規則を消す
```

## ビルド

Visual Studio 2022 Build Tools(C コンパイラ)で `build.bat`。`iivnc-server.exe` ができます。
アイコンは `python tools/make-icon.py` で作り直せます。
